# Milestone 2 verification report

Technical evaluation only. Sinus is not a medical device; these results are not a clinical validation.

This report records the system verification of Milestone 2, the portable real-time C++ library (`libs/sinus-dsp`) and the reference functions it is checked against (`dsp/`), at its release ([`sdp.md`](../regulatory/sdp.md) §3, activities 6 and 7; §6; §8). It is written once for the release and is not regenerated. It holds no evaluation result of its own: the results are in the reports generated by the validation scripts, [`qrs-ec57-report.md`](qrs-ec57-report.md) and [`qrs-ec57-subset-report.md`](qrs-ec57-subset-report.md), and in the equivalence results produced by CI; every figure quoted below is copied from the section of the report that it names, or from a recorded run named in the text.

Date of the verification: 2026-10-11.

**One Milestone 2 requirement is not met: SRS-029 (three of its 11 criteria). It is a known anomaly, tied to OP-074, and is listed in section 8 with its measured results. Every other requirement of Milestone 2 is verified.**

## 6. Results that need the complete databases

These tests are skipped in CI, where only the subset is available (`sdp.md` §6). They were run on 2026-10-11 and the results are those of section 3; the figures come from [`qrs-ec57-report.md`](qrs-ec57-report.md).

**SRS-007, QRS detection performance (Milestone 1 requirement, System level).** 7 of 7 tests pass. Section "Performance targets": gross Se 99.73 %, gross +P 99.83 %, target ≥ 99.50 % for each (TP 91034, FN 251, FP 158; section "Results per record"). The figures are those of the Milestone 1 report: the detection chain did not change. They hold for the library: SRS-038 shows identical detections and counts.

**SRS-023, detection at the start of real recordings.** 5 of 5 tests pass; the independent recount equals the report. Section "Start of stream", "Targets": gross Se 99.70 % and gross +P 99.80 %, target ≥ 99.50 % for each, both pass (1440 segments of 60 s; TP 105167, FN 314, FP 214; average Se 99.70 %, +P 99.78 %).

*Method correction of 2026-10-09 (approved by the project owner).* The first run of this evaluation processed each segment only up to its last sample. Detection reports a beat a fraction of a second after it (at most 2876 samples, SRS-021), so the beats at the end of each segment were never reported and counted as false negatives. The first result was gross Se **99.42 %** (TP 104864, FN 617; the requirement allows at most 527 FN), +P 99.81 %; of the 617 false negatives, **319 lay in the last 0.3 s of the segments**, and only 44 within 2 s to 10 s after the start. The method was corrected, not the detector: each segment is now continued on the record for min(2876, samples left) samples (48 segments have a shorter continuation), and only reference beats and reliable detections whose index lies in the segment are scored. The detection algorithm and its parameters are unchanged. The correction was made after the first results were seen, and it is stated in the report itself ("Method correction"); the first-run result is recorded here as required by `sdp.md` §6.

**SRS-038, detection of the library on the reference databases.** `libs/sinus-dsp/tests/system/test_srs_038_detection_on_databases.py` (62 tests) recounts the detections of the release-build library on the 48 records of the MIT-BIH Arrhythmia Database and the 12 records of the Noise Stress Test Database with the EC57 evaluation of `dsp`: **60 of 60 records have identical detection indices and identical TP, FN and FP** to the reference. `dsp/scripts/compare_library.py` (test `test_srs_038_compare_library_script.py`) exits 0 on the same data. Hence the SRS-007 figures above hold for the library. All 60 records have 650 000 samples at 360 Hz, so the whole length of the longest records is covered.

**SRS-029, signal quality index on the noise stress records.** NOT MET; see section 7.

## 7. Known anomaly: SRS-029 not met

**Requirement:** SRS-029, signal quality index on the noise stress records (System). **Open point:** OP-074 (target Milestone 3). **Risk analysis:** [`risk-analysis.md`](../regulatory/risk-analysis.md) v0.4.3 (revision 0.4.2: RC-007, HAZ-002 and HAZ-006). Measured by the test engineer on the real databases; the figures of `qrs-ec57-report.md`, section "Signal quality index" (subsection "Criteria"), are reproduced by an independent recount in the system test. **8 of the 11 criteria are met and 3 are not.**

| Criterion | Measured | Required | Result |
|---|---|---|---|
| Median index from 24 dB to −6 dB | 0.8185, 0.7503, 0.5764, 0.3938, 0.3455, 0.3566 | non-increasing | **fail** (rises from 0 dB to −6 dB) |
| Median index at −6 dB and at 24 dB | 0.3566, 0.8185 | lower at −6 dB | pass |
| Usable windows, records 118 and 119 from 5:00 | 100.00 % | ≥ 95.00 % | pass |
| Usable windows at 24 dB | 100.00 % | ≥ 90.00 % | pass |
| Usable windows at 18 dB | 100.00 % | ≥ 90.00 % | pass |
| Usable windows at 6 dB | 24.31 % | ≤ 20.00 % | **fail** |
| Usable windows at 0 dB | 1.73 % | ≤ 20.00 % | pass |
| Usable windows at −6 dB | 9.56 % | ≤ 20.00 % | pass |
| Usable windows, noise record bw | 2.84 % | ≤ 10.00 % | pass |
| Usable windows, noise record em | 14.37 % | ≤ 10.00 % | **fail** |
| Usable windows, noise record ma | 3.95 % | ≤ 10.00 % | pass |

Further figures (OP-074): at 6 dB, record 118e06 21.6 % and record 119e06 27.0 % usable; for record em, 246 windows have an index between 0.45 and 0.50, just under the usable threshold of 0.50; the median has a flat floor around 0.35 at low SNR, where the index no longer tells degraded levels apart. The 12 dB level, without a criterion, is 84.28 % usable.

**Effect.** At 6 dB and for electrode motion noise, more windows than allowed are marked usable, so a heart rate computed from a degraded signal can be presented as valid (HAZ-006, HAZ-002); at 0 dB and below the index marks nearly all windows as not usable. No display of the index exists before Milestone 3 (OP-072), so no user is exposed in this milestone.

**Decision (project owner, 2026-10-09).** The usable threshold, fixed in the approved design before the evaluation, is not re-tuned; the criteria of SRS-029 are not changed. Nothing was tuned on the evaluation data, and no parameter of the index was changed after its results were seen. The failure stays visible: the system test reports it, and the report marks the three criteria `fail`. The options for Milestone 3 are in OP-074: (a) improve the index and evaluate it again, reporting the new results as tuned on the evaluation data, or (b) narrow the use of the index and amend SRS-029 by decision of the project owner. The project owner's acceptance of this known anomaly for the release is requested (section 10).
