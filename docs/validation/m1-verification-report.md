# Milestone 1 verification report

Technical evaluation only. Sinus is not a medical device; these results are not a clinical validation.

This report records the system verification of Milestone 1, the Python reference (`dsp/`), at its release ([`sdp.md`](../regulatory/sdp.md) §3, activities 6 and 7; §6; §8). It is written once for the release and is not regenerated. It holds no evaluation result of its own: the results are in the reports generated by the validation scripts, [`qrs-ec57-report.md`](qrs-ec57-report.md) and [`qrs-ec57-subset-report.md`](qrs-ec57-subset-report.md), and every figure quoted below is copied from the section of the generated report that it names.

## 7. Deviations from the targets

- **SRS-007:** none. Both gross values meet the target (section 4). The target applies to the gross values; per-record values have no target. Seven records are below 99.50 % in Se or +P: 105, 108, 116, 201, 203, 208 and 210 (`qrs-ec57-report.md`, sections "Results per record", "Lowest sensitivity" and "Lowest positive predictivity"). What these failures mean for HAZ-001 and HAZ-002 is assessed in [`risk-analysis.md`](../regulatory/risk-analysis.md) (probabilities of HAZ-001 and HAZ-002 with the Milestone 1 results); a listing of each false negative and false positive is the input to OP-056 in Milestone 2.
- **SRS-014:** no pass threshold is set (OP-031); the results are in `qrs-ec57-report.md`, section "Noise stress test".
- **Tuning on the evaluation data** (`sdp.md` §6): none. Every detection parameter and rule is the one fixed in the approved design before the first run on the MIT-BIH Arrhythmia Database (decision on OP-056 of 2026-10-01). Since the commit that introduced the detection chain (`1995d2b`, 2026-09-30), `qrs.py`, `filters.py` and `pipeline.py` have changed only in comments and docstrings. The results are therefore not tuned on the evaluation data; they still come from databases used during development (OP-029).
